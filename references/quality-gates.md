# 质量门禁、分支与提交纪律

门禁全在本地、由 PM 在 commit 前逐项核对，全绿才 commit。CI 不作为门禁依赖。

## 1. 通用门禁（所有项目）

门禁采用**基线口径**：每个任务建分支时捕获基线快照（lint / 测试输出存
`.miemou/YYYYMM/DD/<任务号>-baseline.md`），门禁标准是「**不劣于基线**」——不新增任何失败即放行；
主分支存量红灯不阻塞新任务。与任务无关的存量失败硬修会违反外科手术式改动，禁止；
存量红灯在收尾回报中列明即可。

- [ ] lint 检查无新增报告（命令取自项目约定卡；与基线对比）
- [ ] format 无新增问题（同上）
- [ ] **项目测试不劣于基线**：跑法与范围按约定卡（项目惯例跑定向子集就跑子集、跑全量就跑全量）；
  对比基线快照，不新增失败/错误；基线中已存在的失败列明不修；
  项目无测试基建时退化为「新增非平凡逻辑自带的小测试或断言自检」并如实回报，不硬造测试凑门禁
- [ ] warnings 视为错误的项目：不新增任何 warning（存量 warning 列明）
- [ ] 新文件符合项目文件头/许可证惯例（如有）
- [ ] 改动可逐行追溯到任务包（外科手术式改动检查）
- [ ] 涉及依赖清单改动：lockfile 按约定卡流程重新生成并保持一致，随改动一并提交
- [ ] 涉及用户可见字符串：约定卡的专项流程（i18n 等）走完
- [ ] 无临时产物混入暂存区（`git status` 逐一核对；`.miemou/` 类路径不入库）

## 2. 项目注入门禁

约定卡「质量门禁」「专项流程」两节列出的项目特有守卫（守卫测试、清单一致性检查等）逐项执行。
约定卡没写 → L0/L1 问操作者有无必跑守卫；L2 不停机等待，记入回报
（「项目守卫未确认」风险项），下轮补确认。

## 3. 分支纪律

- 一任务一分支，从开发主分支切出；命名 `feat|fix|docs/<任务号>-<slug>`。
- 建分支后立即捕获基线快照（§1），门禁全程以基线口径核对。
- 分支刷新与合并整合**一律由 PM 执行**（子 agent 被禁止 rebase/merge/checkout 主分支）；
  触发时机：每次合并前、开发主分支出现新合并时。
- 合并回开发主分支固定流程（确定性，无需临场决策）：
  ① PM 将开发主分支最新提交 rebase 进任务分支（冲突此时由 PM 解决）
  ② 快速复跑受影响的门禁项（对比基线）
  ③ `--ff-only` 合并——rebase 之后 ff 必然成立。
- 合并前确认：工作树干净、分支只含本任务改动、门禁基线口径全绿。
- 在途分支超过 3 条 → 暂停开工新任务，先收敛存量。
- **并行实现必须 worktree 隔离**：实现/自测类任务默认串行（单工作树不支持多分支并行检出）；
  确需并行实现时，每个并行任务 `git worktree add .miemou/worktrees/<任务号> <分支>`，
  派发 prompt 写明 worktree 路径，子 agent 在该路径内工作；合并完成后
  `git worktree remove` 清理，不留残留目录。

## 4. 提交纪律

- 提交信息按约定卡规范；约定卡未写时跟随项目 git log 现状（读最近提交提炼，不要猜），
  无历史可参考时按 §7 兜底规范（`<type>: <摘要>`）并在回报中说明。
- 一个任务至少一个可追溯 commit；不在 commit message 里写技术细节长文（细节进方案文档或任务回传）。
- lockfile 随依赖清单改动一并提交。

## 5. 临时产物约定

- 一切中间产物（辅助脚本、验收截图、离屏渲染图、调试 dump、API 响应缓存）写入**项目内**
  `.miemou/`（或约定卡指定目录）；**禁止**写入系统临时目录（`/tmp`、`/var/folders/...`、
  `~/.cache`）或项目内其他位置。
- **日期两级归档**：中间文档按创建当天的日期落入 `.miemou/YYYYMM/DD/`
  （如 `.miemou/202611/19/`），日期目录不存在就按当天日期逐级创建；
  产物不散落在 `.miemou/` 根目录，文件名不带日期（日期由目录承载）。
- 理由：系统临时目录有清理策略、跨会话不可追溯，操作者无法目检验收产物；集中在 `.miemou/`
  并按日期分层，便于按天定位、结项后一次清理，避免散落文件污染工作树。
- 执行细则：子 agent prompt 中显式指定产物路径
  （`.miemou/YYYYMM/DD/<任务号或主题>-<用途>.<ext>`，日期取当天，文件名不加日期前缀）；
  需操作者目检的验收产物保留至按授权档位确认（L0/L1 操作者逐项确认；L2 收尾呈报）后再清理，纯调试产物结项即删；`.miemou/` 永不入库，
  commit 前确认无 `.miemou/` 路径混入暂存区。
- 仅有的两个根级例外：`.miemou/state.md`（任务状态台账，见下节——需跨轮存活，不入日期目录）
  与 `.miemou/worktrees/`（并行实现的隔离检出，非文档产物，不按日期归档）。

### 5.1 任务状态台账（.miemou/state.md）

所有任务来源共用的在途状态文件，位于 `.miemou/` 根，**会话中断恢复的第一依据**。
每个在途/近期任务一节：

```markdown
## <任务号> <标题>
- 状态：排期中 / 实现中 / 自测中 / 门禁中 / 待合并 / 已合并 / 受阻 / 放弃
- 分支：<分支名>（worktree 路径，如有）
- 来源与回写位置：<清单路径+条目 / issue 号 / 对话轮次>
- 进度：<流水线当前步骤>
- 回传摘要：<子 agent 回传的关键结论：改动文件清单、自测证据、门禁逐项结果、基线快照路径>
- 下一步：<恢复时执行的第一个动作>
```

更新纪律：

- **首写时机**：队列确认后立即为每个在队任务创建任务节（状态：排期中）——
  台账首写不晚于队列确认，恢复逻辑依赖任务节已存在。
- 每次状态跃迁（派发、回传、门禁核对、合并、受阻、放弃）**立即**更新本文件——
  子 agent 回传的证据摘录落盘于此，不依赖会话上下文存活；会话一断，上下文里的回传即丢失。
- 任务到达终态（已合并 / 受阻转待排期 / 放弃）后保留该节，直到本轮收尾回报完成。
- 台账是**工作树级**恢复机制：覆盖会话中断与分支切换（未跟踪文件跨分支存活）；
  re-clone 或 `git clean -fd` 后台账丢失，此时以来源回写记录（清单勾选 / issue 评论）
  与 `git branch` 勘察为恢复依据。

## 6. 中止与受阻

- **红灯修复回路**（测试失败 / 门禁红灯时）：PM 附测试回传**全文**（失败输出、定位分析、
  原改动文件清单）再派**原开发子 agent** 修复 → 重测。同一任务预算 **3 轮**
  （与回传格式打回预算独立计，见 team-model.md §5）；
  超限标受阻（原因写明卡在第几轮、最后一轮的失败证据），回报操作者，不再无限乒乓。
- **轮级熔断**：连续 2 个任务受阻 → 暂停本轮剩余队列，收尾回报（受阻清单、原因、下期建议），
  不继续消耗。
- 任务受阻（依赖缺失、红灯超预算、需操作者裁决且档位为 L0）→ 在任务来源处标记受阻原因与依赖，
  回到排期；不悬挂半成品分支不报。
- 已建分支的任务被放弃 → 删除分支（worktree 先 remove 再删分支），不留孤儿。
- 任何成员发现改动会波及其他在途任务 → 立即上报 PM 重排，不擅自扩大改动面。

## 7. 通用默认兜底

项目无任何约定文档、操作者也不提供规则时（模式一被明确跳过的场景，
兜底路径内不设阻塞门——问操作者会卡死无人值守轮）：

- 命令前缀：无
- lint/format：从 lockfile/依赖清单推断（Python 用 ruff；JS/TS 用 eslint + prettier）；
  推断不出则跳过该项并在回报中如实说明
- 测试：按项目测试框架的目录约定执行，范围依项目惯例；惯例不明时先跑涉及模块的子集
- 分支模型：有 `dev`/`develop` 分支用它，否则直接用 `main`
- 提交规范：跟随 git log 现状；无历史可参考时用 `<type>: <摘要>` 简洁风格
  （type 取 feat/fix/docs），并在回报中说明所用规范
- 中间产物：项目内 `.miemou/`，按日期两级目录归档（无 .gitignore 条目时先补一条）
